# 任务3：高赞评论优先队列

## 目标

任务3解决的是“AI 和前端不应固定处理原始顺序前 50 条评论”的问题。后端需要在进入 AI 批处理和审核队列之前，先选出更值得处理的评论：优先高点赞帖子，再优先高点赞评论，并尽量保证每个帖子先只选一条评论。

本任务不禁用 MediaCrawler。现有 `/api/ad-intel/run` 在缓存未命中时仍会调用 `run_crawler(...)`，
最终系统可以继续使用 MediaCrawler 获取真实数据。本轮开发和测试阶段不启动 MediaCrawler、
不登录小红书、不发送真实评论；测试全部使用本地假数据和标准化 payload。

## 数据流

1. `normalize_dataset` 保留原始 `comment_table` 和 `content_table`。
2. `enrich_with_priority_comments` 生成：
   - `priority_comment_table`：优先进入 AI 批处理和前端审核的评论。
   - `comment_selection_meta`：选择策略、评论总数、有效评论数、入选评论数、覆盖帖子数。
3. LangGraph、SSE 评论流、逐评论后台文案生成、`/task/{task_id}/insights` 审核队列优先使用 `priority_comment_table`。
4. 前端只展示后端给出的优先队列顺序，并提供“刷新评论”和“复制文案”。

## 选择规则

策略实现集中在 `app/services/comment_selector.py`。调用方使用 `CommentSelectionConfig` 配置帖子排序字段、评论点赞字段、意图词、首轮每帖入选数和策略版本；默认实例为 `DEFAULT_SELECTION_CONFIG`。后期如果要调整权重或切换策略，不需要改路由、LangGraph 或前端，只需要替换配置或新增选择器实现。

- 帖子优先级：`like_count`、`comment_count`、`collect_count`、`share_count`、`feature_table.ad_fit_score` 降序。
- 评论优先级：`like_count` 降序，兼容测试数据中的 legacy `likes` 字段；同赞数下参考“求链接、求推荐、好用吗、价格、敏感肌、踩雷”等意图词。
- 第一轮：每个帖子最多入选 1 条最高优先级评论。
- 第二轮：如果未达到默认 50 条，再按帖子优先级循环补齐第二、第三条评论。
- 空评论、重复评论会被过滤；缺少帖子元数据的评论会保留在队列末尾作为补位。

## 接口字段

`GET /api/ad-intel/task/{task_id}/insights` 新增：

- `comment_selection_meta.strategy_version`
- `comment_selection_meta.total_comments`
- `comment_selection_meta.valid_comments`
- `comment_selection_meta.selected_comments`
- `comment_selection_meta.covered_posts`

`review_queue` 单条评论新增：

- `comment_like_count`
- `post_like_count`
- `selection_rank`
- `selection_reason`

## 测试要求

- 后端单元测试覆盖高赞帖子排序、每帖先取一条、补齐逻辑、`likes` 兼容、`raw_data.comments` 同步。
- 路由测试覆盖 `review_queue` 优先使用 `priority_comment_table`。
- 前端测试覆盖刷新 comments insights、复制文案而非发送。
- 总体验证不运行 MediaCrawler，但保留生产路径中的 MediaCrawler 调用能力。
